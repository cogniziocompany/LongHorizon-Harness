The overseer has been hand-building this table every five minutes by querying each run's snapshot and
reconstructing round numbers from raw events:

    run        round   last event
    a69d150    4/6     1m ago
    9d20e13    6/8     7m ago

be."*

**There are TWO audiences and the task fails if it only serves one:**
 1. **A human looking at fleet.easybutt0n.ai** - sees fleet-wide progress without clicking into runs.
 2. **The orchestrator agent** - gets the same picture from ONE cheap call instead of N snapshot
    fetches parsed by hand.

## SCOPE

1. **Extend OverviewPage** so each active run shows, without navigating away: current round / max
   rounds, current role, time since last event, and status. **Expandable in place** - clicking a run
   expands to its rounds; expanding a round shows the per-role sessions underneath; that is where the
   live feed belongs, per Paxton. **Reuse `RunPage`'s existing fetchers and `socket.ts`** - if you
   find yourself writing a second websocket client or a second API layer, stop and reuse.
2. **Do not fetch N snapshots from the browser.** If an aggregate endpoint is needed, add ONE to the
   fleet API that returns every active run with its round/role/last-event in a single response, and
   have both the page and the orchestrator use it. Say what you added.
3. **Serve the orchestrator explicitly.** The same aggregate must be consumable by a script - stable
   JSON, documented shape. **State the exact call** the overseer should make each tick to replace its
   hand-rolled table. That sentence in the PR body is a deliverable, not a nicety.
4. **"No events yet" must be distinguishable from "stalled".** A run launched 30 seconds ago and a run
   whose executor has been silent for 25 minutes look identical if you only show "last event: none".
   The overseer nearly killed a healthy run over exactly this. Show elapsed-since-launch as well as
   elapsed-since-last-event, and do not label anything "stalled" that is merely new.
5. **The badge must not lie.** The overview's connection badge previously read "connected" while zero
   nodes were registered - it described the socket, not registration. Whatever you render, make it say
   what it actually measures.
