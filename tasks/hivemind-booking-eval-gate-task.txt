## HOW THE GATE WORKS - read these before changing anything

`.github/workflows/eval-gate.yml` (triggers on PRs to main and pushes to main):
    python evals/run_evals.py --suite deterministic --source ci-hosted --report out/eval-report.json
    python scripts/eval_gate.py --from-report out/eval-report.json
and a separate live job:
    python evals/run_evals.py --suite live ... ; python scripts/eval_gate.py ... --cases live

`cases.yaml` documents its own schema in its header. Per case: `id`, `suite`
(deterministic = offline, every PR | live = LiteLLM gateway), `pytest` (the target run_evals
invokes), `required` (tiers where the gate FAILS without a fresh pass; dev = feature-branch PRs,
prod = PRs into main + go-live), `threshold` (omit = all-pass), `rsi_risk` (low = fixable by
whitelisted config/data changes -> bot PR; high = code/math regression -> escalate),
`rsi_fix_globs`.
