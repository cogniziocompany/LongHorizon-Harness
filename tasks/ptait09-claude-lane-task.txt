================================================================================
THE DEFECT - already diagnosed, DO NOT RE-DERIVE IT
================================================================================
Any call to `POST https://ptait09.easybutt0n.ai/claude`, or `/exec` with `"shell":"claude"`, fails
immediately with:

    '"C:\Program Files\nodejs\claude.cmd"' is not recognized as an internal or external command

ROOT CAUSE: `CLAUDE_PATH` in the runner's `.env` points at a file that does not exist.

    .env line            CLAUDE_PATH=C:\Program Files\nodejs\claude.cmd
    does it exist?       NO - that directory holds only node.exe, npm, npm.cmd, npm.ps1,
                         nodevars.bat, node_modules
    where claude IS      C:\Windows\system32\config\systemprofile\AppData\Roaming\npm\claude.cmd
                         (runs; reports 2.1.81)
    also present         C:\Users\PaxtonTait\AppData\Roaming\npm\claude.cmd (user-profile install)
    runner identity      NT AUTHORITY\SYSTEM  (USERNAME=PTAIT09$;
                         APPDATA=C:\Windows\system32\config\systemprofile\AppData\Roaming)

WHY THE EXPLICIT PATH IS FATAL: `src/runner.js:43-73` defines `resolveClaudePath()`, which probes the
SYSTEM-profile npm path, then `%APPDATA%\npm`, then `Program Files\nodejs` - **but only when
`CLAUDE_PATH` is unset.** `CLAUDE_PATH_EXPLICIT = Boolean(process.env.CLAUDE_PATH)` short-circuits
the probe and the bogus path goes straight to `cmd.exe` via `shell:true`
(`execCli`/`spawnCli`, :288-305).
**This is config drift, not a quoting bug.** `safeExe`/`winQuote` are working correctly - the handoff
proves it by reproducing the identical failure from a plain PowerShell prompt on the box.

================================================================================
THE FIX - option 1, per the handoff's own recommendation
================================================================================
 1. **DELETE the `CLAUDE_PATH` line from the runner's `.env`** and restart the service.
    `resolveClaudePath()` then finds the SYSTEM-profile `claude.cmd` on its own, which is the
    intended design (the code comment calls this "handoff pitfall #2").
    Option 2 - pinning `CLAUDE_PATH=C:\Windows\system32\config\systemprofile\AppData\Roaming\npm\claude.cmd`
    - re-introduces exactly the brittleness that caused this outage. **Prefer option 1 and say why
    if you choose otherwise.**

 2. *** RESTART VIA THE WINDOWS SERVICE, NOT pm2. *** The supervisor is the Windows service
    `ptait09-runner` (LocalSystem), binary `svc\publish\easysvc.exe service-run --config
    svc\runner.svc.json`. A pm2 daemon (pid 12764) is ALSO running on the box but **does not serve
    :7334** - restarting pm2 would look like it worked and change nothing. That trap is the main
    reason this task exists as a written procedure rather than a one-liner.

 3. Back up `.env` before editing (timestamped copy). **Do not print, log or commit any value from
    it** - it is a live runner config. Record only the variable NAME you removed.
