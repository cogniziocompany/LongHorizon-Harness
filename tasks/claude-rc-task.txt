HARD FACTS (verified 2026-09-06; encode them, do not re-derive): `claude remote-control` (CLI 2.1.x) is a server: flags --name, --spawn same-dir|worktree|session, --capacity N, --permission-mode, --continue, --session-id, --debug-file; the process must stay alive; it gives up after ~10 min of network outage, so restart-on-exit is mandatory. Auth needs a FULL-SCOPE /login credential; CLAUDE_CODE_OAUTH_TOKEN (setup-token) and ANTHROPIC_API_KEY are refused ("requires a full-scope login token"); a custom ANTHROPIC_BASE_URL breaks it; DISABLE_TELEMETRY, DO_NOT_TRACK, CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC each disable it. Therefore the RC process gets a clean env and its own credential file (never the runner's .env or the SYSTEM-profile CLAUDE_CODE_OAUTH_TOKEN). Workspace trust must already be accepted for the cwd (projects[<dir>].hasTrustDialogAccepted in the profile's .claude.json); the home dir is never trusted, so cwd = <home>\source (Windows) / ~/source (Linux). Re-running remote-control within ~4 h re-attaches the sessions it served. easysvc health probe is optional (empty health.url disables it, svc/HealthProbe.cs:19); restart-on-exit with backoff is always on. Docker is NOT the place (compose runs only sidecars); RC runs natively next to the runner. Never restart easysvc services from inside the runner (kills the caller).
