PART D - how this joins the token work already in flight
================================================================================

92806f2 on perf/role-context-caps makes the three context-injection ceilings configurable
(--role-history-chars, --role-verified-context-chars, --auditor-output-chars), wired through
run_default so project config works too. Values deliberately unchanged; behaviour-neutral.
Lowering them is a separate EVIDENCED change (task 94), because truncation is a CORRECTNESS
risk: drop an auditor's rejection reason and the manager repeats the mistake.

The auditor-report injection is the real compressible term. role_prompts.py lines 678-705
read the flattened string item.auditor_report and inject the assigned subtask (<=1,600 chars)
plus _clip_preserve(report, 5000) of raw prose per round - about 1,650 tokens/round until it
hits the 100,000-char ceiling. Meanwhile AuditReport (types.py lines 75-88) ALREADY CARRIES
exactly the fields that must stay verbatim: status, missing, blockers, integrity_status,
contract_audit_status, plus pre-compacted state_summary / action_guidance. The harness
computes the compact memory and then DISCARDS it. Replacing the prose blob with the
structured fields plus retrieval-on-demand is about 10 lines/round instead of about 1,650 -
roughly a 16x cut on the dominant term. Only `supersedes` is missing from the schema.

Lowering the executor's prompt size that way is what makes a 128K local executor viable. If
the 256K option holds up, it is still worth doing for cost but stops being a blocker.
