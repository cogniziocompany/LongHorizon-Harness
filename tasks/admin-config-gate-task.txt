## Context

Every repo deploys through the `qa-gate.yml` workflow in this repo, which runs a suite and posts a commit status the caller polls. Today it checks that services *work* (LiteLLM completions, billing SPA auth config, CE checkpoints). It does not check that admin *configuration* matches between UAT and PROD, and it captures no screenshots. Promotions have been going out with undetected config drift, and the biggest source is invisible to any repo scan: LiteLLM runs `store_model_in_db: true`, so models and MCP servers added through its admin UI live in Postgres and never appear in `litellm-config.yaml`. The same is true of the billing service's `app_configuration` table and the ops control center's runtime state.

Decision (confirmed with the user): snapshot what the **live** system serves through its admin API and admin UI, never the repo YAML. ## Design summary

- **One new standalone suite** `admin-config-acceptance/` (Playwright, like `oidc-acceptance/`) with per-surface modules. One `npm ci`, one Playwright config with a `setup-<surface>` login project that saves `storageState`, and one `<surface>` project per admin surface.
- **A manifest** `admin-config-manifest.yml` is the single source of truth for: env base URLs, auth type, the live endpoints to snapshot, sort keys, redaction patterns, parity rules per key path, and the admin pages to screenshot.
- **Snapshot** = normalized, redacted JSON per surface+env. **Parity** = per-path rule: `equal` (default), `differ` (must exist, values may differ: hostnames, keys), `ignore` (timestamps, spend, ids), `present`.
- **Two comparisons per run**: live(env) vs live(`compare_to`) and live(env) vs committed golden in `config-baselines/<surface>/<env>.json`. Goldens change only through reviewed PRs.
- **Gate targets** `admin-litellm`, `admin-ops`, `admin-billing`, all served by one `admin` job in `qa-gate.yml`. Status contexts follow the existing pattern, e.g. `cognizioware-qa/admin-litellm-uat`.
- **Failure tags**: mismatches and 403-after-login are `drift`; 401/5xx/login errors are `real`; selector timeouts on a 200 page are `test-debt`. Delivered via an explicit `[tag:…]` prefix the reporter learns to read.

## Risks and how the plan treats them

- **Entra interrupts**: "Stay signed in" (handled, as in `ce-auth.ts`), "Keep your account secure" (click Skip, else fail `real`), Conditional Access requiring a compliant device (qa-host is not managed; fail `real` and stop).
