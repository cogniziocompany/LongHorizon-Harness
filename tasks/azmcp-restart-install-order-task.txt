ROOT CAUSE, read from the merged file itself (bottom of
`infrastructure/register-mcp-tools-stack.py`):

`main()` calls `sys.exit(1)` when the Portainer stack update/create API call fails (see the
`UPDATE FAILED` / `FAILED` branches around line ~166-176). That Portainer failure is EXPECTED AND
PERMANENT for this stack — the deploy workflow's own step is literally named "Sync Portainer stack

path \"/data/compose/68/docker/gateway-guides-mcp\" not found","_status":500}`). Because `sys.exit(1)`
raises `SystemExit`, the interpreter never reaches the next top-level statement, so
`install_supervised_restart()` has NEVER RUN on CT202 — not once, on any deploy, since PR #182
merged. The bug is the ORDERING/control-flow in 214d's own change, not Portainer and not the sync
allowlist (which 214d already fixed correctly).
