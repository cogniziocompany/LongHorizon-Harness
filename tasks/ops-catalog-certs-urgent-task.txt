================================================================================

Paxton: "this is emprty secren https://ops.easybutt0n.ai/certs its empty screen".

302 to the auth proxy, `/certs` included:

    /  /overview  /catalog  /certs  /e2e  /admin-centres  /audit    -> 302 each

So the route resolves and the page is being served; it renders empty **after** authentication. The
fault is inside the component or its data source, not in Caddy or oauth2-proxy.

Find out which of these it is and say so explicitly:
  (a) the data source returns nothing (no certs discovered / a probe failing silently),
  (b) the data source errors and the component swallows it into an empty render,

**(b) is the one to look hardest for.** An empty screen where a caught exception should have been
surfaced is the same defect class as the guest-auth bug and the "Step 0 of 7" spinner: **a failure
rendering as a blank rather than as an error.** Whatever the cause, the page must end up saying
something - "no certificates found", or the error - and never render blank.
