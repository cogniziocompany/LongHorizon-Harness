STEP 1 - src/lh_harness/workspace_identity.py (new, top-level sibling of queue.py; must NOT import webapi or supervisor, three callers need it). Frozen dataclass WorkspaceIdentity{path, key=normcase(realpath(path)), is_git, repo_id, branch, git_common_dir, resolved_at, error}. Exactly TWO read-only subprocesses per uncached path via a private _run_git:
 (a) git --no-optional-locks -C <path> rev-parse --path-format=absolute --git-common-dir --abbrev-ref HEAD, falling back without --path-format for git < 2.31 then absolutising manually - the primary tree returns a RELATIVE .git while a worktree returns absolute, so they never compare equal otherwise;
 (b) git --no-optional-locks -C <path> config --get remote.origin.url - config --get, NOT `remote get-url`: same answer, cannot touch the network, cannot take a lock.
 Mirror the existing subprocess idiom in agent_registry.py (capture_output, text, timeout=5.0, check=False, try/except returning a safe empty value). Set env GIT_OPTIONAL_LOCKS=0, GIT_TERMINAL_PROMPT=0, GIT_ASKPASS=echo, and CREATE_NO_WINDOW on win32.
 TWO HARD RULES IN THE MODULE DOCSTRING: (1) NEVER invoke any `git worktree` subcommand - Windows git treats WSL-created worktrees as prunable and prune/remove destroys live trees; `worktree list` is the tempting adjacent API and must stay out. (2) --no-optional-locks / GIT_OPTIONAL_LOCKS=0 is not optional: a bare rev-parse can refresh and lock the index while an executor is mid-commit, which would make the harness CAUSE the collision it reports.
 repo_id: normalised remote (strip credentials, lowercase host, scp-form to host/org/repo, drop .git) -> remote:<host>/<path>; else commondir:<sha256(common_dir)[:16]> so worktree siblings collapse without a remote; else None. A None repo_id groups with nothing except an exact key. Fail open everywhere (return None, never raise - follow utils/run_boundary.py). Module-level cache + lock, TTL 60s including negative results, bounded LRU 256 because `workspace` is caller-supplied on POST /api/runs. Expose resolve_many(paths, budget_seconds=3.0) so a hung filesystem cannot stall a tick. DO NOT build a /mnt/c to C:\ translator - one process sees one namespace and a heuristic would manufacture false same_tree claims; WSL/Windows twins are still caught by the shared remote.

STEP 2 - src/lh_harness/contention.py (new, pure functions, no I/O). Tiers ascending: same_repo < same_repo_same_branch < shared_git_dir < same_tree.
 same_tree = equal identity.key (the doctrine violation); shared_git_dir = equal git_common_dir, different key (worktree siblings sharing refs/objects); same_repo_same_branch = equal repo_id and equal non-null branch (the -b mid-PR hazard); same_repo = equal repo_id only (the intended throughput pattern, informational).
 Members are ACTIVE runs only - a pending entry has not started and cannot collide - and note that ACTIVE_STATUSES includes waiting_approval, so a gate-waiting run IS a member, which is exactly the doctrine's "a gate-waiting run still holds its tree". Group by repo_id or f"path:{key}" (one group per real situation, no pair explosion); severity is the max over member pairs. contention_id = sha256(canonical_json({group_key, severity, sorted members}))[:16] so a standing contention yields the same id every tick and is not re-emitted, while a membership/branch/severity change yields a new id (one cleared, one detected). Cap at 50 groups / 20 members with a truncated flag.

STEP 3 - launcher integration (src/lh_harness/launcher.py). In _run_pass(), after `active = self._active_runs()` and BEFORE the launch loop, call self._check_contention(active) inside try/except Exception, emitting a queue.error service event with the truncated message - the bare except is deliberate and must carry a comment saying a git failure must never abort the pass. _check_eligibility IS UNTOUCHED - broadening it would be a blocking behaviour change, the one thing ruled out. _check_contention builds participants from active, resolves identities via resolve_many, detects groups, filters by a configurable min_emit_severity, diffs against self._contentions, and emits detected/cleared. _emit_contention calls the existing _emit_run_event ONCE PER MEMBER (each record stamped with that member's own run_id, because events.py rejects an event whose run_id disagrees with the run requesting it - peers go in the payload) plus one _emit_service_event.
 Event names: fleet.contention.detected and fleet.contention.cleared. The pair gives clearing plus restart-safe dedupe, and both suffixes are inert to _status_for() in events.py, which turns .started/.completed/.failed/.pending into lifecycle status - so naming here is load-bearing.
