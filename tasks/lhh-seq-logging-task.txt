CONTEXT (verbatim from the source plan)
================================================================================
LongHorizon-Harness (the lh-harness Python app) currently has NO centralized logging at all: only two
files (manager.py, fleet/reporter.py) call logging.getLogger, there is no logging.basicConfig /
dictConfig anywhere in src/lh_harness, and the only structured telemetry that exists today is
(a) per-run JSONL files on disk and (b) an opt-in fleet-admin HTTPS reporter (fleet.easybutt0n.ai).
Goal: a small, fail-open, zero-new-dependency log handler that ships Python logging records to Seq
(https://seq.easybutt0n.ai), wired through the same env-var / EnvironmentFile pattern already used for
fleet reporting, identical across WSL dev, CT110 systemd prod, and lh-harness-node Docker fleet nodes.

APPROACH: mirror the existing FleetReporter design (src/lh_harness/fleet/reporter.py) - same lifecycle
idioms - rather than pull in a third-party package (e.g. seqlog). The app stays dependency-free: it uses
only stdlib urllib.request for the fleet HTTP path; requests/httpx are NOT runtime deps (pyproject.toml).

================================================================================
STEP 1 - NEW MODULE src/lh_harness/seq_logging.py
================================================================================
A logging.Handler subclass (SeqLogHandler) + a singleton installer, following fleet/reporter.py's shape:
 - ENABLE CONDITION: only when SEQ_URL is set (mirrors LH_HARNESS_FLEET_URL gating). SEQ_API_KEY
   optional in code, documented as REQUIRED for prod. Handler requires both non-empty to ship.
 - TRANSPORT: Seq raw CLEF ingestion - POST {SEQ_URL}/api/events/raw?clef, header X-Seq-ApiKey: <key>,
   body = newline-delimited JSON, one compact CLEF object per record:
   {"@t": "...Z", "@l": "Information", "@m": "...", "@x": "<exception text>", "logger": "...",
    "app": "lh-harness", "node": "...", ...extra}
   Level mapping: DEBUG->Verbose (or Debug), INFO->Information, WARNING->Warning, ERROR->Error,
   CRITICAL->Fatal.
 - DELIVERY: background daemon thread + bounded queue.Queue, batched every ~2s (same
   _BATCH_INTERVAL_SECONDS idea), gzip body, bounded retry (3 attempts, same backoff tuple), never
   blocks the emitting thread, 4xx NOT retried and warn-once. urllib.request / urllib.error only.
 - FAILURE ISOLATION: emit() never raises; unreachable Seq degrades to a queue-full warn-once,
   exactly like the fleet reporter's _warn_once.
 - SINGLETON ACCESSOR: get_seq_handler() / install_seq_logging() analogous to get_reporter().

================================================================================
STEP 2 - WIRE-UP POINT src/lh_harness/cli.py: main()   (cli.py ~L391)
================================================================================
main() is the single true entry point for every subcommand (run, web, dashboard, plugins). At the top,
before subcommand dispatch:
 1. logging.basicConfig(level=<LH_HARNESS_LOG_LEVEL, default INFO>, ...) ONCE - nothing configures the
    root logger today (only WARNING+ reaches stderr via the handler of last resort).
 2. seq_logging.install_seq_logging() - attaches SeqLogHandler to the ROOT logger when SEQ_URL is set,
    so uvicorn/FastAPI access + error logs from webapi/server.py flow to Seq too (explicit decision).
 3. No-op identically to FleetReporter when SEQ_URL is unset.
