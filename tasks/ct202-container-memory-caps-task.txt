================================================================================
THE DEFECT, STATED PLAINLY
================================================================================

`azure-mcp-backend` carries a 16 GiB memory limit inside a container that has 20 GiB total. So the
compose file PERMITS a single non-critical MCP backend to consume 80% of CT202 and starve
everything else in it, including the production router that the entire agent fleet routes through.
The limit is doing the opposite of its job: it is large enough to guarantee the CT dies first.

--- CORRECTION, MEASURED 2026-09-17 04:39 PT BY SCHEDULED TICK #405 -----------------------------
THERE IS NO 16 GiB LIMIT. azure-mcp-backend runs with NO memory limit at all.
  docker inspect -f '{{.HostConfig.Memory}}'  ->  0
  cgroup memory.max (docker-a854d4f9...scope) ->  max
  litellm, read the same way, returns 6442450944 (6 GiB) - so the reader distinguishes a real
  limit from an absent one; "max" is not a read failure.
The "16 GiB" quoted above (and in the queue note, and in PR #153's own comment) is the DISPLAY
COLUMN of `docker stats`, which falls back to a total when no limit is set. It was never a
configured cap. The DEPLOYED compose on CT202 confirms it: mem_limit appears for litellm (6g) and
the browser services (2g), and NOWHERE in the azure-mcp-backend block.

This makes the defect WORSE, not different: the backend is permitted ALL 20 GiB, not 16.

CONSEQUENCE FOR PR #153 (task/122-ct202-mem-limits, OPEN, MERGEABLE, base main, 15 lines, does not
touch litellm-config.yaml): it ADDS `mem_limit: 16g` + `memswap_limit: 16g` to azure-mcp-backend.
That is an improvement on unlimited, but it DOES NOT SATISFY STEP 1 BELOW: 16g (azure) + 6g
(litellm) + 5x2g (browser services) = 32 GiB of limits inside a 20 GiB CT, so the router can still
be starved before azure's own cap bites. PR #153's comment argues 16g because azmcp "peaks at
~15.7 GiB" - but that peak was the LEAK running unbounded, not demand. Do not treat #153 as
closing this task; either raise its cap budget to fit 20 GiB or supersede it.
