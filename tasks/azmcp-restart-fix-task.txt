File: `infrastructure/scripts/azure-mcp-supervised-restart.sh` (the script added by PR #181).
The script runs under `set -euo pipefail` and its own header states its purpose is to NEVER fail
silently — every outcome (SKIPPED/FAILED/RESTARTED) must write a reason line. A code review found
two places where that guarantee is actually violated by `set -e` itself:

1. Around the pre-restart status read:
   `status="$(docker inspect -f '{{.State.Status}}' "$CONTAINER")"`
   This is an unguarded command substitution assigned directly. Under `set -e`, if `docker inspect`
   exits non-zero here (container removed/recreated, daemon hiccup), the WHOLE SCRIPT exits
   immediately at that line — the `if` block below that is supposed to `emit FAILED reason=...` for
   exactly this case never runs, and no reason line is ever written. FIX: guard the assignment so a
   failing `docker inspect` is caught and routed through the existing FAILED-emission path instead of
   killing the script (e.g. `if ! status="$(docker inspect -f '{{.State.Status}}' "$CONTAINER" 2>&1)"; then emit FAILED reason=...; exit 1; fi`, matching the style already used a few lines earlier for the `docker inspect -f '{{.Id}}'` read, which IS correctly guarded with `if !`).

2. The identical bug exists at the post-restart status read:
   `pstatus="$(docker inspect -f '{{.State.Status}}' "$CONTAINER")"`
   Same fix: guard the assignment so a failing inspect right after `docker restart` is caught and
   logged as FAILED (`reason=post-restart-inspect-failed` or similar) instead of silently exiting
   with nothing written to the log for that cron fire.
