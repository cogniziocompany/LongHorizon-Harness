================================================================================
WHY OUTCOME-LEVEL AND NOT A PINO RETROFIT - this reasoning is settled, do not redo it
================================================================================
The obvious reading of "cover the runner and suites" is to retrofit pino into all four. That is the
WRONG build, for four measured reasons:
  - litellm-acceptance and billing-acceptance have ZERO dependencies (node --test); oidc-acceptance
    has only @playwright/test. pino + pino-seq would be their first dependency ever.
  - All four are ONE-SHOT processes that exit immediately. pino-seq batches on a timer, so each
    would need bespoke flush wiring across 5 runner flow scripts, a Playwright reporter and two
    node:test hooks - seven fragile exit paths, each a silent-log-loss bug.
  - The suites sit OUTSIDE the npm workspace (root glob is packages/*), so there is no clean shared
    module.
  - Their raw stdout is nearly worthless anyway (0 / 1 / 5 console lines). THE SIGNAL IS THE OUTCOMES.

scripts/gate-report.mjs is already the universal choke point: it normalizes ALL FOUR result formats
(qa-run, playwright, tap, merge); emits target/env/profile/callerSha/score/passed/failed/skipped/
durationMs/tagCounts and per-check {name,status,tag,message,httpStatus,expected,actual} where `tag`
is the existing drift / test-debt / real / unclassified classification; already uses global fetch
(L107) with ZERO dependencies; and is already top-level-await (L279), so `await postToSeq(...)`
needs NO flush machinery.
