DECISIONS - ALREADY SETTLED 2026-09-08. IMPLEMENT THESE; DO NOT RE-DECIDE THEM. State any disagreement with evidence in the completion report, but build what is written here.
 1. ROUTE PER RUN, OBSERVE PER ROUND. The worker command and the adapters are built once and both resume paths re-read owner.role_configs, so a mid-run switch has no support anywhere in the code. Per-round failures append to route.history; re-routing happens at the next bind (a new run, or a resume). A transient state is waited out within the episode, not routed around.
 2. NO RETRY of a round that already worked, on a better model. BOUNDED RELAUNCH for a PRE-ROUND refusal only (Paxton, 2026-09-08 interview): when rounds_run == 0 and the abort reason is provider rate limit, quota, authentication, model unavailable, or the new not_permitted, the launcher marks that model in availability, fails the original entry with the reason recorded, and creates a new pending entry carrying retry_of and attempt = n+1. Each attempt MUST bind a route that differs from every earlier attempt for the failing role, or wait until an earlier state's TTL has expired; when neither is possible the entry is refused naming everything tried. Default cap `[routing] max_relaunch = 3` (the original plus two), configurable. A run that produced rounds is never restarted - that double-spends the budget that was scarce to begin with and hides whether the task or the model failed.
 3. NEVER PULL a model. Pulling is a host-level change, and the standing rule is no host change without an explicit human go. A cold model is a legal candidate at tier=adequate with a warning, and the rationale must name it so a person can decide to load it.
 4. OVERRIDE IS A QUEUE-ENTRY FIELD, never code. It is set through the API, the Hydra panel or the chat tool, carries `by` and `reason`, is validated against the key-scoped catalogue, and is honoured even when availability disagrees - recorded as tier=override with the disagreement in the rationale. It SURVIVES RESUME: continue copies the owner minus the resume-cleared owner keys (route must NOT be in that set), and retry passes owner.role_configs through and also accepts newly supplied roles.
